Antigravity Manager 详细介绍：账号管理、额度监控与本地 API 网关

发表于 2026-11-21 分类于 技术 阅读次数：

如果同时使用 Antigravity 客户端和多款 AI 编程工具，账号切换、模型额度和工具配置很容易分散在不同地方。Antigravity Manager 把这些操作集中到一个桌面应用中：管理 Google 账号、查看额度、切换 Antigravity 使用的账号，并通过本地 API 网关连接其他编程工具。本文依据项目中文 README及项目文档，介绍它的能力、上手流程和使用边界。

Antigravity Manager 是什么？

Antigravity Manager 面向 Antigravity Classic、Antigravity IDE 和 agy CLI 用户。它有两个主要使用方向：一是管理这些客户端所用的 Google 账号，二是启动本地 API 网关，让 Claude Code、Codex、OpenCode 等工具通过网关发起模型请求。

可以把它理解为账号与额度控制台，加上本地模型接口适配层。它不是模型提供方；能看到哪些模型、能否成功调用，仍取决于账号权限、剩余额度、上游服务和具体请求。客户端账号切换与网关的请求调度也是两套独立策略，不能把“切换了客户端账号”理解为“网关此后只使用该账号”。项目 README｜账号与额度说明

核心功能

1. 集中管理 Google 账号

可以在应用中通过默认浏览器完成授权，添加 Google 账号；如果本机已有相关会话，也可以先预览，再选择导入。账号列表提供状态查看、批量操作及 JSON 导入导出。每个账号的卡片会展示额度信息，并标明哪些 Antigravity 客户端正在使用它。

这适合需要在多个账号间查看状态的用户。导入前应核对账号来源和预览内容；移除 Manager 中的账号，也不等同于让该账号退出所有官方客户端。账号模块文档

2. 查看模型额度与重置时间

Manager 可以手动刷新或在后台定时刷新额度，展示可用模型、剩余比例和重置时间。额度视图覆盖 5 小时滚动窗口、每周周期和合并视图，还能按模型过滤、排序。这样可以先看清账号状态，再决定是否切换客户端账号或让网关接收请求。

需要注意，界面中的额度数据是基于已取得的上游信息，不等于“下一次请求必定成功”；模型权限、限速和上游状态仍可能变化。项目还提供可选的每周预热功能，但它默认关闭，启用后会发送真实模型请求，可能消耗额度或 AI credits。项目 README｜账号模块文档

3. 切换 Antigravity 客户端账号

顶部工具栏可以选择目标客户端：Classic、IDE 或 agy CLI，再把它切换到指定账号。桌面客户端切换时可能需要重启，因此先保存其中未完成的工作；切换后，最好在官方客户端里核对实际登录身份。若首次启动出现条款确认，也要在官方客户端完成。

还可以按需启用自动切换。项目文档说明，监控默认每五分钟轮询一次额度；当当前账号遇到限速，或关键模型及适用的共享额度低于 5% 时，可按策略轮换官方客户端使用的账号。它不会直接决定本地 API 网关每次请求使用哪个账号。项目 README｜账号模块文档

4. 提供本地 API 网关

内置网关对外提供兼容 OpenAI Chat / Responses、Anthropic Messages 和原生 Gemini 的接口，并支持流式传输、思考过程保留及模型映射。它的作用是把不同客户端的请求接到 Manager 管理的账号与上游模型。具体协议能力会受到请求功能、目标模型和上游行为影响，不能把“兼容某协议”理解为完整复刻该服务的所有 API。项目 README｜协议兼容说明

Manager 提供 Claude Code、Codex 和 OpenCode 的配置入口，也可以将页面显示的网关地址与 API Key 填入其他兼容客户端。配置写入成功只表示本地设置已保存；需要重启目标工具，实际发送请求，再到流量监控查看请求与结果，才能确认链路打通。工具配置说明

5. Playground、诊断与桌面体验

应用内的 Playground 可调试 Prompt、并排比较两个模型、使用多个账号并行测试，还能查看首字延迟（TTFT）和吞吐量等基准指标。流量监控提供请求耗时、错误详情和诊断编号，便于定位“配置已写入，但调用失败”的问题。

此外，项目支持本地账号快照备份与恢复、独立的客户端身份配置、系统托盘、额度告警、紧凑布局，以及简体中文、英文和俄语界面。项目 README

下载与安装

优先从项目 Releases 页面下载，并以该页面当前提供的文件及变更说明为准。桌面安装包已内置运行时，普通安装无需为了运行应用而另装 Node.js 或 pnpm。

平台 架构与安装包
Windows x64、ARM64：NSIS .exe；x64 另有 MSI
macOS Apple Silicon arm64、Intel x64：DMG 或免安装 ZIP
Linux x64、ARM64：AppImage、DEB、RPM

下载时注意区分 arm64 / aarch64 与 x64 / amd64 / x86_64。Windows 升级已有版本时，建议沿用原来的安装包类型；macOS 用户打开前应先将应用拖到 /Applications；Linux 用户按发行版选择包格式，AppImage 还需相应系统运行环境。Arch Linux 有社区维护的 AUR 包；Nix 用户也可参考项目 README 中的 flake 使用方式。安装说明

首次使用：两条常见路径

路径一：只管理 Antigravity 账号

  1. 打开 Manager，通过浏览器授权添加账号，或预览后导入本机已有会话。
  2. 刷新额度，确认账号状态、可用模型、剩余比例和重置时间。
  3. 在顶部工具栏选择 Classic、IDE 或 agy CLI。
  4. 将目标客户端切换到选定账号，必要时重启客户端，并在官方客户端核验身份。
  5. 如确实需要，再开启自动切换，并了解其触发条件。

路径二：连接 Claude Code、Codex 或 OpenCode

  1. 先完成账号添加和额度刷新，确认目标模型对账号可用。
  2. 打开 API 反代 页面，阅读风险提示；首次启动服务时完成确认。
  3. 在编程工具配置卡片中选择目标工具和模型，检查设置后应用；其他客户端则使用页面给出的地址与 API Key。
  4. 重新打开编程工具，发送一条测试请求，并在流量监控中核对请求和结果。

工具配置可能修改本机客户端设置。项目会为 Claude Code 和 Codex 的初次写入保存备份；但“断开连接”与“恢复备份”的效果不同，后者可能覆盖后来对同一设置文件所做的改动。动手前最好阅读配置与恢复说明。

必须了解的数据与账号风险

本地凭据需要自行保护。 项目明确说明，云账号 OAuth token 以明文 JSON 形式保存在本地 SQLite 数据库中；能读取数据库的人，也可能读取这些 token。完整账号导出和备份还可能包含 token 与代理凭据。因此要保护应用数据目录、备份文件和网关 API Key，不要把数据库、备份、私人提示词或未经检查的日志上传到公开 Issue。项目 README｜安全与数据边界

反代有服务条款和账号风险。 项目作者提示，反向代理用途可能违反服务提供方条款，导致账号受限或暂停；软件不保证账号安全、模型可用性或持续访问。首次从桌面端启动代理时会显示风险确认；若要让其他设备连接，还应先检查监听地址、网络访问范围和 API Key 的保管方式。

许可限制也要看清。 仓库采用 CC BY-NC-SA 4.0 许可，项目声明禁止商业使用，仅供教育与研究目的。将它用于工作流之前，应该结合项目许可、适用法律及上游服务条款自行判断。项目 README

常见问题怎么排查？

现象 优先检查
安装后无法启动 操作系统、CPU 架构与安装包是否匹配；记录版本与具体报错
登录或切换失败 网络与代理设置、官方客户端首次设置、错误详情和诊断编号
编程工具无法调用模型 网关是否启动、账号是否有权限和额度、地址与 Key 是否正确
工具显示已配置却没有流量 重启工具，并检查环境变量、命令行参数或直登插件是否覆盖配置

反馈问题时，可在项目 Issues附上复现步骤、系统与架构、应用版本和诊断编号，同时先检查并移除敏感信息。排错与反馈说明

适合谁使用？

如果你经常在 Antigravity 的多个客户端或多个 Google 账号间切换，希望集中查看额度，或者需要为 AI 编程工具配置一个本地兼容接口，Antigravity Manager 值得了解。最稳妥的上手顺序是：先管理一个账号并确认额度，再切换一个客户端；需要网关时，再连接一款工具并用真实请求验证。 这样每一步出现问题时都能更快定位原因。

本文依据项目文档整理，功能与安装包可能随版本变化；实际操作以项目中文 README和Releases 页面为准。
